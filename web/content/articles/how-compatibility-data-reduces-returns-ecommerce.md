Returns from “wrong fit” are **catalog intelligence failures**, not only UX issues. High-quality compatibility edges and substitution logic—maintained by **Compatibility Agent** / **Product Graph Agent**—shrink the decision error rate before checkout and in post-purchase agent flows (RMA prevention).

Return dashboards spike “wrong part” reasons; teams get asked for prettier PDPs. **Voomi**-class HVAC programs at **1M+ SKUs** cannot answer that with copy—**compatibility** + **multipack** structure is what gates bad picks before ship, alongside automation that cut publish time **~85%**. **Profitero** would never fix retailer label drift by rewriting marketing text—they re-train on **>95% P/R** constraints. **JCPenney** Mirakl returns often trace **taxonomy/family** errors masquerading as fitment—structure, not tone.

## Proof Points

- **Voomi Supply:** at **1M+ SKUs** / **200M+ ASIN** scale, **compatibility** + **multipack** truth are co-requisites with listing automation that cut publish time **~85%**—draft should tie returns to **pre-purchase constraint checks** (voltage, thread, pack) caught before bad picks ship, not claim unpublished return-rate percentages.
- **Profitero:** treat fitment rows like taxonomy labels: weak supervision + pipelines that hold **>95% precision/recall**—misclassification cost is the same failure class as wrong-fit picks in parts/HVAC.
- **JCPenney:** marketplace returns from **taxonomy misalignment** (right SKU, wrong browse context) masquerading as fitment issues.
- **Failure scenario:** **missing attributes** on voltage/thread pitch → customer selects visually similar incompatible SKU → return.
